# Domain docs

This repo uses a single-context layout: root `CONTEXT.md` for domain terms
and `docs/adr/` for architecture decisions.

Before exploring an area, read root `CONTEXT.md` if it exists and the ADRs
relevant to that area. Proceed if a document is absent. Domain modeling
creates or updates context documents when terms and decisions are resolved.

Use the glossary's terms in issue titles, proposals, hypotheses, and tests.
If an output conflicts with an ADR, identify the conflict explicitly.
